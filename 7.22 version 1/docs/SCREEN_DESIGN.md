# 화면 설계 가이드 (Stitch 목업용)

- 문서버전: v0.1
- 작성일: 2026-07-21
- 목적: [PRD.md](PRD.md) 기준으로 Stitch에서 화면 목업을 만들 때 그대로 붙여넣을 수 있는
  화면별 스펙 + 프롬프트를 정리한 문서

이 문서의 각 화면 항목 하단 "Stitch 프롬프트"를 그대로 복사해 Stitch 입력창에 붙여넣고,
필요하면 세부 문구만 다듬어 사용하면 됩니다.

---

## 0. 공통 디자인 방향

- **톤앤매너**: 발전/플랜트 설비 관리 시스템다운 신뢰감 있는 톤. 화려한 장식보다 정보 가독성 우선.
- **컬러**: 딥블루(#1E3A5F 계열) 포인트 + 뉴트럴 그레이 배경, 상태 강조는 신호색(빨강=조치중/위험, 초록=조치완료)
- **레이아웃**: 좌측 고정 사이드바 내비게이션 + 상단 헤더(현재 화면명, 검색 단축 진입) + 본문 영역
- **사이드바 메뉴**: 대시보드 / 고장이력 / 설비목록 / 이력 마이그레이션
- **디바이스**: PC(데스크톱) 우선 레이아웃, 태블릿에서도 표가 깨지지 않도록 반응형 고려
- **공통 컴포넌트**: 데이터 테이블(정렬/페이지네이션), 필터 바, 상태 배지(조치완료/조치중), 파일 업로드 드롭존, 토스트 알림

공통 프롬프트 접두어(각 화면 프롬프트 앞에 붙이면 톤이 일관됩니다):

> "발전소/플랜트 열원설비 고장이력 관리 시스템의 웹 화면입니다. 톤앤매너는 딥블루와 뉴트럴 그레이 위주의
> 신뢰감 있고 정보 밀도가 높은 산업용 대시보드 스타일입니다. 좌측에 고정 사이드바(대시보드, 고장이력,
> 설비목록, 이력 마이그레이션 메뉴)가 있고 상단에 헤더가 있습니다."

## 1. 대시보드

**목적**: 전체 고장 현황을 한눈에 요약해서 보여주는 첫 진입 화면

**구성 요소**
- 상단 요약 카드 4개: 이번달 고장건수, 조치중 건수(강조), 다발 설비 Top1, 전체 누적 건수
- 월별/연도별 고장 발생 추이 꺾은선/막대 그래프
- 고장분야별 비율 파이차트 (CES/CHP(복합)/CHP(일반)/DH/소각장)
- 지사별 고장건수 비교 막대그래프
- 다발 설비 Top 10 랭킹 테이블
- 최근 등록된 고장이력 5건 리스트 (클릭 시 상세로 이동)

**Stitch 프롬프트**
> (공통 접두어) + "대시보드 화면을 만들어주세요. 상단에 이번달 고장건수, 조치중 건수, 다발 설비 Top1,
> 누적 건수 4개의 요약 카드를 가로로 배치하고, 그 아래 월별 고장 추이 그래프(꺾은선), 고장분야별 비율
> 파이차트, 지사별 고장건수 막대그래프를 2단 그리드로 배치합니다. 하단에는 다발 설비 Top10 랭킹 표와
> 최근 등록된 고장이력 리스트를 나란히 보여주세요."

## 2. 고장이력 목록/검색

**목적**: 조건별로 과거 고장이력을 검색·조회하는 메인 작업 화면

**구성 요소**
- 상단 필터 바: 지사 드롭다운, 열공급시설 드롭다운(지사 선택 시 연동), 발생기간(From~To), 고장분야,
  상태(조치완료/조치중), 키워드 검색창
- "신규 등록" 버튼 (우측 상단, 강조 버튼) → 화면 4로 이동
- 결과 테이블 컬럼: 발생일시, 지사, 열공급시설, 설비명/기기명, 고장분야, 고장제목, 상태(배지), 작성자
- 행 클릭 시 상세화면(화면 3)으로 이동
- 하단 페이지네이션, "엑셀로 내보내기" 버튼

**Stitch 프롬프트**
> (공통 접두어) + "고장이력 검색 화면을 만들어주세요. 상단에 지사, 열공급시설, 발생기간(시작~종료),
> 고장분야, 상태, 키워드 입력의 필터 바가 있고 우측에 '신규 등록' 버튼을 강조색으로 배치합니다.
> 아래는 발생일시, 지사, 열공급시설, 설비명, 고장분야, 고장제목, 상태(배지 형태), 작성자 컬럼을 가진
> 데이터 테이블이며 상태는 조치완료(초록 배지)/조치중(빨강 배지)으로 구분됩니다. 하단에 페이지네이션과
> '엑셀로 내보내기' 버튼을 배치해주세요."

## 3. 고장이력 상세

**목적**: 개별 고장이력 1건의 전체 내용을 열람 (고장상보 원문 양식과 유사한 레이아웃)

**구성 요소**
- 상단: 고장제목, 상태 배지, 발생일시~복구일시, 수정/삭제 버튼
- 기본정보 섹션: 지사, 열공급시설, 설비명, 기기명(고장위치), 고장분야
- 공급중단 현황 섹션: APT 세대수, 건물 개소, 중단시간, 기간
- 담당자 섹션: 고장원인 담당자(부서/이름), 책임자(부서/이름)
- 상세 서술 섹션(순서대로): 상황, 보안·경보장치 동작상태, 원인(4M+1분석), 장애현황, 응급처리, 복구내용, 재발방지대책
- 첨부파일 섹션: 원본 고장상보 문서(PDF/HWP) + 기타 첨부파일 목록, 다운로드 아이콘
- 데이터 출처 표시(수동입력/문서추출/엑셀이관) - 작은 라벨로

**Stitch 프롬프트**
> (공통 접두어) + "고장이력 상세보기 화면을 만들어주세요. 최상단에 고장제목과 상태 배지, 발생~복구일시,
> 우측에 수정/삭제 버튼을 배치합니다. 그 아래 기본정보(지사, 열공급시설, 설비명, 기기명, 고장분야)를
> 카드 형태로, 공급중단 현황(APT 세대수, 건물 개소, 중단시간, 기간)을 별도 카드로 보여줍니다. 이어서
> 상황, 원인(4M+1분석), 장애현황, 응급처리, 복구내용, 재발방지대책을 순서대로 읽기 좋은 섹션으로
> 나열하고, 맨 아래 첨부파일(PDF/엑셀/한글 아이콘 구분) 목록과 다운로드 버튼을 배치해주세요."

## 4. 고장이력 등록/수정 (문서 자동추출 포함)

**목적**: 신규 고장이력을 직접 입력하거나, 고장상보 PDF/HWP를 업로드해 자동 추출된 내용을 검토 후 저장

**구성 요소**
- 상단: "파일로 자동 채우기" 업로드 드롭존 (PDF/HWP만 허용, 안내문구 표시) — 선택 사항이며 건너뛰고
  직접 입력도 가능
- 업로드 시: 로딩 상태 → 추출 완료 후 아래 입력폼에 값이 자동으로 채워짐 + "자동 추출됨" 안내 배너
  (필드별로 자동채움 하이라이트 표시)
- 입력 폼 섹션 구성은 상세화면(화면 3)과 동일한 순서: 기본정보 → 공급중단현황 → 담당자 →
  상황/원인/장애현황/응급처리/복구내용/재발방지대책 → 첨부파일
- 각 텍스트 영역은 자유서술이 길 수 있으므로 여러 줄 입력(textarea)
- 하단: "임시저장" / "저장" 버튼, 저장 전 필수값 미입력 시 인라인 오류 표시

**Stitch 프롬프트**
> (공통 접두어) + "고장이력 등록 화면을 만들어주세요. 최상단에 'PDF/HWP 파일을 올리면 자동으로
> 내용을 채워줍니다'라는 안내와 함께 파일 업로드 드롭존을 배치하고, 업로드 후에는 '자동 추출 완료 -
> 내용을 검토하고 저장해주세요'라는 안내 배너를 보여줍니다. 그 아래 지사, 열공급시설, 설비명, 기기명,
> 고장분야를 입력하는 기본정보 폼, 공급중단 현황(세대수/건물개소/중단시간) 입력 영역, 담당자/책임자
> 입력 영역이 이어지고, 상황/원인/장애현황/응급처리/복구내용/재발방지대책을 입력하는 여러 개의 텍스트
> 영역이 순서대로 나열됩니다. 맨 아래 첨부파일 목록과 '임시저장', '저장' 버튼을 배치해주세요."

## 5. 설비 간이목록 관리

**목적**: 고장이력에 연결할 설비 목록을 등록/조회

**구성 요소**
- 상단 필터: 지사, 열공급시설
- "설비 추가" 버튼
- 테이블 컬럼: 설비명, 설비코드, 지사, 열공급시설, 연결된 고장이력 건수(클릭 시 화면2로 필터 이동)
- 행 클릭 시 간단한 수정 모달(설비명/코드/지사/열공급시설)

**Stitch 프롬프트**
> (공통 접두어) + "설비 목록 관리 화면을 만들어주세요. 상단에 지사/열공급시설 필터와 우측에
> '설비 추가' 버튼이 있고, 아래 설비명, 설비코드, 지사, 열공급시설, 연결된 고장이력 건수 컬럼을 가진
> 테이블을 배치합니다. 행을 클릭하면 설비 정보를 수정하는 모달 창이 뜨는 형태로 디자인해주세요."

## 6. 과거 이력 엑셀 일괄 마이그레이션

**목적**: 기존 "2020~고장상보 overview" 형태의 엑셀을 한 번에 업로드해 초기 데이터로 적재 (1회성/관리자용)

**구성 요소**
- 안내 문구: "지사, 열공급시설, 보고유형, 고장제목, 고장분야, 고장설비, 고장기기명, 상태, 발생일,
  조치완료일, 고장내용, 결재진행 컬럼 순서의 엑셀만 지원" 등 포맷 안내
- 파일 업로드 드롭존
- 업로드 후: 컬럼 매핑 미리보기 테이블 (엑셀 헤더 ↔ 시스템 필드 매칭 확인)
- 검증 결과 요약: 총 행수, 정상 건수, 오류 건수(빨간색 강조) + 오류 행 상세 리스트(사유 포함)
- "일괄 등록 실행" 버튼 (오류 건 제외하고 진행할지 확인하는 다이얼로그)
- 실행 후 결과 요약(성공/실패 건수)

**Stitch 프롬프트**
> (공통 접두어) + "과거 고장이력 엑셀을 일괄로 업로드하는 관리자용 마이그레이션 화면을 만들어주세요.
> 상단에 지원되는 엑셀 컬럼 형식을 안내하는 문구와 파일 업로드 드롭존이 있습니다. 업로드 후에는
> 엑셀 컬럼과 시스템 필드가 어떻게 매칭되는지 보여주는 미리보기 테이블, 총 행수/정상 건수/오류 건수를
> 보여주는 요약 카드(오류 건수는 빨간색 강조), 오류 행을 사유와 함께 보여주는 리스트가 이어집니다.
> 맨 아래 '일괄 등록 실행' 버튼을 배치해주세요."

## 7. (선택) 엑셀 내보내기 결과

**목적**: 검색 결과를 엑셀로 내보낸 후 다운로드 확인

**구성 요소**
- 내보내기 완료 안내 + 파일명/생성일시
- "다운로드" 버튼
- (선택) 내보낸 조건 요약(어떤 필터로 내보냈는지)

**Stitch 프롬프트**
> (공통 접두어) + "검색 결과를 엑셀로 내보낸 뒤 보여주는 간단한 완료 화면을 만들어주세요. 가운데
> 체크 아이콘과 함께 '엑셀 파일이 생성되었습니다' 메시지, 파일명과 생성일시, '다운로드' 버튼을
> 배치하고 그 아래 어떤 필터 조건으로 내보냈는지 요약해서 보여주세요."

## 작업 순서 제안

1. 화면 1(대시보드) → 2(목록/검색) → 3(상세) → 4(등록/수정) 순으로 먼저 Stitch에서 목업 생성
   (가장 핵심 플로우이자 서로 디자인 톤을 맞춰가는 기준이 됨)
2. 5(설비목록), 6(마이그레이션)은 관리자성 화면이라 후순위로 생성
3. 각 화면 생성 후 이 문서의 "구성 요소" 목록과 대조해 빠진 항목이 없는지 체크
4. Stitch에서 내보낸 결과물(HTML/이미지)을 이 프로젝트 폴더에 저장 후 다음 단계(실제 프론트엔드
   구현)로 넘어갈 때 공유
